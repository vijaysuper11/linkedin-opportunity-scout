# Search Queries (built from the owner's profile)

Do not use a fixed keyword list. Build queries from `config/profile.md` (offer map, focus, engagement types) and `config/search-rules.md`.

## Method
1. Take the capabilities marked `strong` and ranked highest in the owner's current focus. Use `light` ones only as secondary terms.
2. For each, combine a demand frame with the capability term and a synonym. Demand frames:
   - "looking for" / "need" / "hiring" / "seeking" + role or capability
   - "can anyone recommend" / "know a good" + role
   - "[problem] help" (a pain the owner solves, written as the buyer would)
   - engagement words from the owner's wanted types: contract, freelance, project, part-time, consultant, retainer, advisor
3. Add the owner's location or "remote" / "worldwide" only if the owner is open to remote or region-specific work.
4. Exclude negative terms from `config/search-rules.md`.

## LinkedIn post search
Use content search, sort by Latest, date posted past 24 hours. Widen to past week only if results are thin. Run 5 core queries every day (top focus capabilities) and rotate 3 more from the remaining capabilities and problem statements, so each day mixes.

## Public web search patterns
- site:linkedin.com/posts "<demand frame>" "<capability>"
- site:linkedin.com/feed/update "<capability>" "<engagement word>"

## Notes
- If the post links to an employer application page, include that link in the shortlist as an alternative route.
- Record which queries produced shortlisted posts so the weekly review can improve the set.
- Refresh queries whenever the profile is re-read.
